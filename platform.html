About Platform Code

Platform

A fleet is only worth running if you can say what it did and prove it.

Every non-trivial change moves through the same path: recon before planning, a plan a human approves before any code exists, implementation split into slices, and review by something that never watched the code get written.

scout → architect → human gate → builders → reviewers → integrator
01

The work graph

Six specialized nodes, each with one job. Scout does read-only recon and returns verified file:line facts — never a plan, never an opinion. The architect turns those facts into a plan and decides the shape: a single loop when slices share files, a parallel fan-out when three or more are genuinely disjoint. Builders implement one slice each, isolated in their own worktrees, and never review their own work. An integrator proves the whole is coherent, not just that each part passed alone.

02

Guardrails that actually block

Policy that is only written down is policy that gets skipped under deadline. The rules that matter run as hooks that deny the call: a builder cannot write outside the file set approved at the gate, and the commit guard rejects attribution trailers on every agent type. Both fail closed — a broken guardrail denies loudly rather than quietly letting through the thing it exists to stop.

03

Verified, not asserted

Agents report success; that is not evidence. Every run writes shared state each node stamps as its own, so the edges can be audited after the fact — a review with no build behind it, an integrator that ran over a rejected slice, a run marked done with a slice never built. Closing a run checks the work landed in git, not that a status file says so.
